PACS vs cloud storage: why a folder of DICOM files is not an archive.

Many small centres store studies in generic cloud storage or a shared drive. It works until someone has to find a study, read it or send it. This comparison sets the two side by side without pretending storage is useless.

Who each is for

Storage keeps files. A PACS understands them.

Generic cloud storage is for keeping files safe and available on more than one device. It suits a centre that receives a handful of outside studies a month, or a doctor who wants a backup of CDs. It knows nothing about patients, modalities or reports; it sees a folder.

A PACS is for a centre whose machines produce studies daily. It receives them automatically, indexes them by patient, opens them in a viewer, attaches the report and shares a link with the referrer. Storage is one of the things it does, not the thing it is.

How each works

A folder tree against a DICOM archive

Cloud storage

Someone exports the study from the machine or the console, usually to a USB stick or a network folder, then uploads the folder to the storage account. Folder names become the index: a patient name, a date, whatever the technician typed. To read it, someone downloads the folder and opens it in a viewer installed on their computer. To send it, they share the folder link. Sync clients and shared links make this feel organised for a while.

A PACS

The machine is pointed at the PACS once. From then on every study arrives on its own with the patient details inside the DICOM header, so the index is built from the data rather than from a folder name. The front desk searches by name or ID, the radiologist opens the study in the browser, the report is finalised as a PDF against the study, and the referrer gets a secure link. Backup runs in the background; in a hybrid system such as AuraPACS the local node keeps the centre working when the internet is down and the cloud layer keeps an encrypted offsite copy.

The difference is not where the bytes sit. It is whether the system understands what the bytes are.

How to decide

Where storage stops being enough

Cloud storage is fine, and honestly so, when the centre does not produce studies. A physician who keeps copies of patients' CDs. A clinic that occasionally receives an outside MRI. In both cases the volume is small, the people are few and the folder name is enough.

It stops being fine at three predictable points.

  • Volume. A machine producing studies daily fills a folder tree nobody maintains. Search becomes scrolling.
  • Reading. The radiologist should not be downloading folders. A browser viewer opened from a worklist is the difference between a reading session and a file-management session.
  • Accountability. Patient images in a shared folder with a link anyone can forward is a privacy problem waiting for an incident. A PACS logs who opened what.

If you are already on storage and want to move, the studies can be imported into the PACS so the history is searchable from day one. Ask the vendor for that before signing. Questions

PACS vs cloud storage, answered

Can I use cloud storage as a PACS?

You can store DICOM files there, but you will not get automatic receive from the machine, a patient index, a browser viewer, a worklist, reporting or audited sharing. For a centre with its own modality, that gap is the whole workflow.

Is cloud storage cheaper than a PACS?

In the first months, usually. Storage charges grow with volume every year, and the hidden cost is staff time spent uploading, naming, finding and downloading folders. Compare over several years, not one.

Is it safe to share patient images through a storage link?

A generic share link is not scoped to a patient or a study and leaves no audit trail of who opened it. A PACS shares a link tied to one study, with role-based access and a log of who viewed it.

What about a shared drive on the centre's own network?

A local drive is a less convenient version of the same problem: no index, no viewer, no worklist, and a single disk with no offsite copy. An on-premise PACS uses similar hardware and adds the workflow. See on-premise PACS.

Can old studies in storage be moved into a PACS?

Yes. DICOM files can be imported into the archive and indexed from their headers, so earlier studies become searchable alongside new ones. Confirm the import is included in setup.

Does a PACS still need backup?

Yes. An on-premise PACS needs an offsite copy; a hybrid PACS includes an encrypted cloud copy as part of the design. Ask any vendor where the backup lives and how a restore is tested.
