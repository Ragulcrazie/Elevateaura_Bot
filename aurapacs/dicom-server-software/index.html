What a DICOM server does

A DICOM server is a program that waits on the network for imaging machines to send it studies. Each CT, MR, X-ray or ultrasound is configured with the server's address, port and Application Entity title, and at the end of a scan it transmits the images using the DICOM protocol. The server accepts them, checks the patient and study identifiers inside the files, and stores them.

In AuraPACS the DICOM server runs on the on-premise node. The same node also provides the modality worklist service, which the scanners query to get the day's scheduled patients, and serves the stored studies to the browser viewer. There is no separate product to buy or a second server to run.

Where setups go wrong

Almost every DICOM problem is a configuration mismatch, not a fault.

The protocol is old and dependable. What fails is a wrong port, a mistyped AE title or a firewall nobody mentioned.

AE title mismatch

The scanner is told to send to one AE title and the server is listening under another. The send fails with no useful message on the console.

Port blocked

The node's DICOM port is closed by a Windows firewall rule or a router, so the association never opens.

IP changes overnight

The node gets a new address from DHCP and every modality is now sending into nothing.

Worklist never configured

The scanner can send studies but was never set up to query the worklist, so patient details are still retyped.

Vendor engineer needed for a menu

The modality's DICOM settings are behind a service menu the centre has never opened.

Nobody wrote it down

Six months later nobody remembers which AE title the ultrasound uses.

Questions

DICOM server software, answered.

What is an AE title?

The Application Entity title is the name a DICOM device uses on the network. The node has one, each modality has one, and they must match what is configured on each side for a send or a worklist query to succeed. See What is DICOM.

Which port does the node use?

The node listens on a single configurable port for DICOM connections. The exact value is set at installation and given to you to enter on each modality, along with the node's IP and AE title.

Can our IT person do this without a vendor visit?

Yes, with remote guidance from Elevate Aura over WhatsApp and screen share. The scanner-side settings may need the modality's service engineer if they sit behind a service menu. In Chennai the setup can be done in person.

Does the worklist run on the same server?

Yes. The modality worklist service is part of the AuraPACS node, so the scanner sends studies to and queries scheduled patients from the same address. See DICOM worklist software.

What if a machine does not support DICOM send?

Very old units sometimes cannot send over the network. That is confirmed on a call before setup, so you know which modalities will connect and which need a workaround or replacement.

Does the node need the internet to receive studies?

No. Receiving, the worklist and local viewing run on the centre's network. The internet is used for the encrypted offsite copy, remote reading and WhatsApp links.
